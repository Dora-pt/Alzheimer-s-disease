## 2 里程碑与门禁准则（Gate）

| 门禁 | 时点 | 准入条件 | 退出条件（全部满足才放行） |
|---|---|---|---|
| G0 立项 | M0 | 客户材料到手 | 章程批准；分工确定；仓库建立；原始材料归档 |
| G1 需求基线 | M1 | Q1/Q2/Q5/Q12 已答复 | SRS 评审通过；数据字典完成；原型评审通过；需求基线 v1.0 冻结 |
| G2 设计基线 | M2 | G1 完成 | 架构、数据库、详细设计评审通过；ADR 记录完整 |
| G3 首个可运行版本 | M3 | G2 完成 | 骨架可运行；3 张样板表通过客户演示确认 |
| G4 功能完备 | M4 | G3 完成 | 范围内量表 100% 完成；单元测试记录齐全 |
| G5 测试通过 | M5 | G4 完成 | 用例通过率 ≥95%；无遗留 S1/S2 缺陷 |
| G6 验收交付 | M6 | G5 完成 | 客户验收签字；全套文档交付；维护记录建立 |

> **门禁硬规则**：未通过的门禁不得跳越；逾期未关闭的挂起项由 PM 提报客户裁决，书面记录处理结论。

## 5 质量管理

- **评审**：需求、设计、代码、测试四类评审，均使用检查单并留记录；
- **测试分层**：单元测试（开发自测）→ 集成测试 → 系统测试 → 验收测试；
- **缺陷分级**：S1 致命 / S2 严重 / S3 一般 / S4 轻微；S1 当日响应，S2 两个工作日内；
- **度量**：需求实现率、用例通过率、缺陷密度、缺陷修复周期（周报跟踪）。

## 6 变更控制流程

```
提出变更 → 登记变更单 → 影响分析（范围/工期/成本/质量）
    → 变更评审（PM+TA+相关角色） → 客户确认
    → 是 → 更新计划与基线 → 实施 → 验证 → 关闭
    → 否 → 记录理由 → 关闭
```
